# 自用乐器播放器：收敛后的产品与实现方案

更新日期：2026-09-17。本文取代此前方案中的产品范围、界面参数和首版开发清单。源码分析仍作为技术参考；本次只调整方案，没有实现程序或进行游戏实测。

目标：用户打开一首曲谱，听一下，然后播放。曲谱适配和输入时序由程序负责，不要求用户理解 MIDI、音域、修饰键提前量或调度策略。

## 1. 一个窗口，三个主要动作

空白状态只显示“打开曲谱”，支持拖入 MIDI / TXT，不要求先选择格式或模式。导入后显示曲名、当前进度、试听、播放／暂停、停止。打开其他曲谱的入口继续保留。

```text
曲名                                     打开曲谱

                 当前进度 / 总时长

        试听          播放／暂停          停止

已准备好
```

试听时，“试听”变为“结束试听”；试听与游戏播放互斥。点击播放会结束试听，倒计时期间显示“请切回游戏，3 秒后开始”，可随时取消。停止按钮和全局停止热键始终清晰可见。

主界面不放参数区、轨道表格、日志窗口或适配统计。正常情况只显示“已准备好”“正在播放”等状态；影响听感或阻止播放时才解释原因。

只有两个按需出现的调整入口：

- **换个声部**：在试听附近的次要入口打开候选列表，可逐个试听。默认已选推荐声部，不要求每次选择。不显示声道编号、评分权重或算法名；缺少名称时使用“声部 1”等中性标签，不凭空认定为人声或主旋律。
- **速度**：放在折叠的“播放选项”中，只有“慢一点、原速、快一点”和恢复默认。暂停或停止后生效，不出现 BPM、输入延迟等技术设置。若加快会明显损害旋律，则不给出不可用档位并说明原因。

暂停保留进度并立即松键，继续时短倒计时后从下一音开始；不重吹被中断的长音。停止回到开头。首版不支持拖动进度、循环片段、播放中换曲或实时修改参数。

## 2. 程序自动承担的判断

### 曲谱与旋律

自动识别文件格式。MIDI 排除打击乐声道，从轨道名称、音符数量和重叠情况中推荐一个声部；推荐只是起点，用户仍可通过试听换声部。

固定一种单音处理规则：同刻起音选最高音，新起音截断前音尾部，不恢复被覆盖的伴奏尾音。界面不提供“最高活跃音／优先声部／钢琴适配”等策略切换。先保证一种结果稳定可解释，再根据常用曲子的实际问题改进。

TXT 保留一个严格的小文法，导入后走相同管线。默认节奏由文件内明确标记或统一默认值确定；不把空格、换行猜成延迟。文件无法可靠理解时指出出错位置，附简短格式示例，不静默删除内容或生成猜测的曲谱。

### 音域适配

固定用户实际乐器的键位和音域预设。自动适配可以整体移动八度，但不能改变校准得到的乐器基准音，也不能逐音折返造成旋律跳跃。

实现上只需枚举少量整体八度偏移，优先选择完整覆盖、位移最小的方案。若仍无法完整覆盖，则选覆盖最好且位移最小的方案，不能把缺失音隐藏掉。普通整体八度移动只显示简短状态“已适配音域”，试听使用适配后的音高。

若仍有越界，显示“部分音符超出乐器音域”，提供试听与换声部。默认不自动跳过越界音；只有此时才提供“播放可演奏部分”的一次性选择，不开放一整套折返、丢弃和自动移调参数。首版不自动改变半音调性。

### 演奏速度与输入时序

修饰键等待、最短按住、松键间隔使用内部验证过的默认配置。开发时可记录和调整，正常用户界面不提供这些参数，也不做“高级设置”把整张参数表藏起来。

规划阶段发现音符过密时，先评估小幅减速能否完整保留音符。适配后的建议速度会显示为“已稍微放慢，以保留音符”，并用于试听和播放；必须有内部减速下限，不能悄悄把整首歌拖得很慢。下限与判断标准由开发阶段常用曲目验证后确定，不包装成用户参数。

若明显减速仍不能可靠演奏，显示“这段旋律过密，当前无法完整演奏”，提供换声部；本版不自动大量删音再声称“已准备好”。运行时严重卡顿直接停止并释放，不补发积压音符。

自动适配只依据曲谱和已验证的输入预算。没有游戏反馈，程序就不能宣称自动测出了游戏延迟、帧率或实际漏音率。

## 3. 出问题时给出动作，不让用户排查参数

| 情况 | 显示内容与可用动作 |
|---|---|
| 推荐旋律不合适 | “换个声部”，逐个试听 |
| 尚未切回游戏 | “请切回游戏”，取消倒计时或重新开始 |
| 播放中切出游戏 | “已切出游戏，演奏已停止”；释放输入，不自动恢复 |
| 文件损坏／格式不支持 | 说明文件或文本位置，重新打开曲谱 |
| 无法可靠完整适配 | 说明是音域还是音符过密，试听或换声部 |
| 本机试听不可用 | “当前无法试听”；保留游戏播放能力，不要求配置音源库 |
| 输入发送失败 | “未能发送演奏输入，已停止”；必要时提供一条针对性的处理建议 |
| 松键失败 | 明确显示残留按键及“重试释放”；清理完成前禁止重新播放 |

避免技术错误码占据主界面。详细信息收在“复制诊断信息”入口中，由用户需要反馈问题时使用。成功发送到 Windows 不能作为游戏已发声的证明。

首次使用默认采用当前乐器预设；仅在目标窗口不明确时让用户选一次并记住。若确实需要校准，做成短小引导：播放一段固定音阶，让用户反馈是否正常，不要求手填毫秒或 MIDI 音高。校准流程须由实际游戏验证后设计，首版不虚构自动检测能力。

## 4. 代码也收敛，但保留可靠性

采用此前报告建议的 C# Windows 桌面方向。一个应用项目、一个测试项目足够；按文件区分导入、旋律适配、播放和 Windows 输入，无需插件、事件总线、依赖注入框架或数据库。

内部保留一条数据管线：

`MIDI / TXT → 原曲音符 → 推荐声部与单音旋律 → 音域和速度适配 → 固定物理时序计划 → 试听或游戏输出`

原曲数据不改写，适配结果独立保存来源和原因。试玩与导入都不发送游戏按键；只有用户明确点击播放后才能进入游戏输出。

实际实现必须保留以下几件事：

1. **先缩放音乐时间，再施加固定物理间隔。** 使用绝对时钟调度，运行时用实际发送完成时刻复核间隔，不能用计划时间冒充实际时间。
2. **只有一个播放线程拥有输入。** 停止、暂停、失焦和异常共用释放逻辑；旧会话彻底退出、持有账本清空后才能新建会话。
3. **等待可取消。** 不为满足最短音长拖延停止；紧急松键优先。失焦后不发新的按下事件，但仍释放本工具持有的键。
4. **工作放后台。** 导入、适配在播放前完成；播放中不扫描全曲、不写磁盘、不逐音刷新界面。进度定时读取快照即可，避免持续忙等。
5. **输入与存储边界有检查。** 导入限制文件大小、事件数和曲长；检查 SendInput 返回值，保存失败项供释放重试；设置写入用临时文件替换，失败保留旧文件。

只为输入发送和时间等待保留可替换边界，便于无需游戏的测试。无需为了每个处理步骤都创建接口。诊断先用有限条数的内存记录和结束摘要，发生错误或用户导出时保存；首版不做分位数面板、实时日志仪表盘或独立日志系统。

## 5. 首版交付与验收

先完成输入与停止释放验证，再打通“一首 MIDI → 自动推荐 → 试听 → 播放”，随后接入 TXT、暂停继续、按需声部选择和设置记忆。不要先把旧报告里的全部可选策略实现一遍。

首版保留：本地 MIDI / TXT、推荐声部、单音适配、有限音域／速度适配、试听、播放／暂停、停止、失焦保护和简短诊断。正常用户无需打开设置就能完成一首可适配曲子的播放。

首版不做：在线曲库、账号、云同步、谱面编辑、Android、宏导出、硬件 MIDI 输入、多种归约策略、手动时序参数、拖动跳转、实时变速或自动更新。这些不进入隐藏菜单或预留子系统。

验收主要看两方面：

- **使用是否简单**：默认流程只有打开、试听、播放；无需知道 BPM、声道、移调半音数或毫秒参数；错误提示有下一步动作；试听和播放消费同一份适配结果；自动处理不能隐藏明显的音符损失。
- **行为是否可靠**：变速不压缩输入安全间隔；短音、重复音和跨音区切换能正确规划；失焦、长音中停止、快速停开、发送失败和释放失败都不会留下旧会话继续按键；坏文件可报告；导入和播放不让界面失去响应。

开发测试用可记录的假输入验证这些行为；真正的音域、输入间隔和听感仍需在用户机器及实际游戏版本上验证。本文没有声称这些测试已经执行。
