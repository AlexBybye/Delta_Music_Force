# 首版实现与验证记录

版本：0.1.0。日期：2026-09-17。

## 文件与职责

- ScoreImport.cs：使用 DryWetMIDI 惰性 token 读取；全局 tempo 表、同音 FIFO 配对、格式和规模限制；严格 TXT 解析、行列错误提示。
- Music.cs：纯数据模型、候选排序、保留起音的单音化、整体八度适配、小幅速度适配、物理计划。
- Playback.cs：单线程会话、可取消绝对时钟、实际发送间隔检查、暂停与恢复、停止清理及失败保留。
- WindowsIO.cs：扫描码 SendInput、目标窗口与权限边界、可能持有输入账本、独立逐项释放、winmm 试听。
- MainWindow：单窗口 UI，后台导入／规划，10 Hz 进度快照；使用帮助和按需调整入口。
- Settings.cs：串行临时文件替换写入；加载损坏设置时提示并保留原文件，后续明确保存时才替换。

主流程不依赖大模型。声部推荐按名称、数量和音高排序，属于启发式规则；MIDI 自带音符和时间信息，不是音频识别。

## 时序取舍

先按速度换算目标物理时间，再施加修饰稳定 40 ms、最短按住 45 ms、松键间隔 20 ms、同键重触发 45 ms、最大起音迟到／尾延长各 50 ms 的暂定预算。预算位于代码内部，UI 不提供调参表。

首版每个音结束释放全部本工具持有的键；接受一定的最快密度限制以简化状态。暂不复用跨音鼠标修饰。运行时再根据实际发送完成时刻验证约束；明显卡顿直接停止，不补发积压音符。紧急释放优先于最短音长。

这些参数并非游戏采样周期测量值。没有游戏内反馈，无法保证最终成音。前台检查与输入发送之间存在操作系统级竞态；进程被强杀也无法保证 finally 执行。

## 验证

自建测试程序没有第三方测试框架，以异常断言和非零退出码作为构建门禁。所有输入测试通过假输出完成，不发送真实键盘／鼠标输入。

当前 29 个测试场景覆盖：TXT 节奏／错误定位／限额；MIDI 默认速度／跨轨变速／FIFO 重复音／打击乐排除／损坏文件／超长载荷；单音化／映射／整体八度／显式部分播放／过密拒绝；倍速物理约束／实际发送时刻／晚唤醒不补发／失焦释放／长音停止／不确定发送／释放失败阻止重启／快速停开／暂停恢复不重吹／x64 INPUT 布局／设置损坏保留／一万音符规划性能。

本机一万音符适配约 21–23 ms，仅代表该测试数据与本次机器环境，不是所有 MIDI 导入耗时或游戏响应保证。

UI 冒烟模式通过 WPF 实际窗口渲染，检查空白、已载入、最小窗口和展开选项布局；测试时不注册热键、不创建游戏输出。发现并修复了窄窗口展开选项后按钮被裁切的问题，现在内容可滚动且播放按钮不会被卡片裁切。

尚未验证：真实游戏输入识别、游戏版本对应音高、独占全屏兼容性、游戏高负载下的听感、长时间运行稳定性。下一轮应先使用示例音阶在目标游戏内验证，不能以模拟测试或 API 成功替代这一步。

## 后续迭代边界

保持选曲、试听、播放的主流程。只有出现具体曲谱兼容问题才扩展语法；若加 Markdown，只提取明确标记的曲谱块，不猜测文章中的任意数字。优先根据用户真实曲谱与游戏反馈修正时序，不引入账号、云曲库、编辑器或新参数面板。
